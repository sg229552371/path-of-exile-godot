为以下需求制定实现计划：$ARGUMENTS

遵循原则 1（先想后写）与原则 4（目标驱动执行）。

输出：
1. **理解复述**：用自己的话复述需求；若存在歧义，列出多种解释并**询问**，不要静默选定。
2. **涉及面**：列出将改动的文件 / 场景 / 节点（可用 godot_ai 工具核查现状）。
3. **分步计划**，每步附可验证的成功标准，格式：
   - [步骤] → verify: [如何验证]
4. **剔除项**：指出哪些是"投机性设计"并明确不做（原则 2：极简优先）。
5. **边界**：标明哪些现有代码不应被改动（原则 3：外科手术式改动）。

输出计划后**等待用户确认**再动手实现。
